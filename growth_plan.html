🚄 铁旅 · 用户运营与数值体系规划

把「一个单机小游戏」升级为「一套可运营的产品」——先建用户运营框架，再往框架里填数值。
版本 v0.1 · 2026-08-19 · 适用：铁旅（中国高铁模拟旅程）· 状态：规划稿，待评审后进入开发

0 · 规划思路（先看这页）

核心原则：先有用户运营体系，再调数值；数值服务目标，不是数字本身。

用户运营的完整闭环 = 拉新 → 激活 → 留存 → 变现 → 传播。每一个环节都要有机制（做什么）和数值（奖励多少）。先定义机制，数值只是给机制定价。

拉新邀请 / 分享卡 / 排行榜
→
激活新手任务 / 首乘奖励
→
留存登录奖励 / 每日任务 / 回归礼包
→
变现商家打卡 / 会员 / 皮肤
→
传播邀请码 / 成就卡分享
→
拉新…飞轮循环

运营北极星指标：周活跃里程数（用户每周实际乘车总里程）——它同时反映活跃、深度、内容消耗，比 DAU 更能代表产品价值。

2 · 经济骨架：五类资源，各司其职

游戏资源不是越多越好，而是每一种资源承担一种运营职能，防止"一个金币包打天下"导致数值无法控制。

资源定位运营职能主要获取主要消耗防通胀设计
货币金币 ¥交易货币驱动日常消费登录 / 任务 / 打卡 / 邀请 / 成就车票（核心）、餐车、装饰、活动日产出硬上限 800；大额装饰回收
成长里程 km经验值驱动核心行为（乘车）唯一来源：乘车无（纯积累）不可购买 → 无法氪金跳级
阶段等级成长阶段给老用户特权感里程累计自动升级无指数经验曲线（见 §9）
运营积分运营货币连接线下（打卡）与线上打卡 / 签到 / 分享积分商店兑换（皮肤券/装饰）每季度活动清积分
荣誉收藏成就资产展示型留存车票收藏 / 徽章 / 风景照无纯荣誉，不参与经济
为什么这样分？ 金币负责"花钱的乐趣"，里程负责"成长的尊严"，积分负责"运营的弹性"——三者互不污染，运营想刺激哪个行为，就只调对应资源的产出。

3 · 产出渠道：用户每天为什么来？

3.1 每日登录奖励（7 日循环，断签重置）

第1天第2天第3天第4天第5天第6天第7天
¥100¥120¥140¥160¥180¥220¥300 + 积分50

7 天一个循环、第 7 天大奖 → 制造"快集满了"的沉没成本；断签重置 → 制造"损失厌恶"。这是留存的第一道钩子。

3.2 每日任务（3 个，每天 0 点刷新）

任务行为引导奖励
今日出发：完成 1 次乘车核心行为（坐车）¥80 + 里程记录
窗外风景：拍 1 张风景照玩法深度（拍照系统已有）¥50
线路巡礼：浏览任意线路图/站点浏览停留时长¥30

每日任务常规产出 ≈ ¥460（不含登录奖励）。任务数量控制在 3 个——能一眼做完，不形成负担。

3.3 真实世界打卡（运营扩展点，P3 启用）

打卡方式说明奖励
位置打卡到达某火车站/合作商家附近（GPS 围栏 500m）¥100 + 50 经验 + 积分 30
扫码打卡扫商家/车站二维码（可远程，防作弊）¥100 + 积分 50

打卡是线上游戏 ↔ 线下真实世界的桥：它让"卖家/商家"有理由入驻（用户到店打卡 = 线下导流），也让用户有理由把游戏带出屏幕。

4 · 消耗渠道：金币花在哪？

消耗项价格区间频率作用
车票（核心消耗）¥100 ~ ¥1300（短途~全程）每天 1-3 次最大回收口，吃掉 70% 产出
餐车¥20 ~ ¥60随行程小额零花，制造"顺手消费"
列车涂装¥3000 / 款低频大额回收，给存钱的理由
徽章框 / 头像框¥1500低频荣誉消费
限时活动车次特殊定价活动期节点消费
设计要点： 车票吃掉日常产出（保证"要钱就要坐车"），涂装/徽章框吃掉沉淀金币（防止金币只增不减 = 通胀）。两类消耗缺一不可。

5 · 经济循环图（一个闭环）

阅读方式： 用户每天登录领金币 → 花金币买车票（消费）→ 坐车得里程（成长）→ 升级享折扣（省钱）→ 第二天更愿意回来（留存）→ 回来再领金币（循环）。每一环都为下一环创造动机，这就是"数值驱动运营"。

钩子机制作用启用阶段

7 · 增长飞轮：用户帮你拉用户

邀请码注册+500/200 · 首乘+300/300
→
成就分享卡旅程/成就生成图片
→
周里程排行榜好友榜 + 全国榜
→
打卡合影分享线下打卡照 + 水印
→
新用户 → 邀请…飞轮自转

设计要点：

  • 奖励要分两段：注册发一部分、首乘再发一部分 → 过滤"注册即走"的羊毛党，保证拉来的是真玩家。
  • 分享要带品牌：分享卡自动带"铁旅"标识 + 邀请码，每次转发 = 一次免费广告。
  • 排行只奖里程不奖金币：排行榜用"荣誉"驱动（称号/徽章），避免排行榜变成刷金币工具。

8 · 用户分层管理：不同的人，不同的打法

分层定义识别信号运营策略
新用户注册 < 7 天未完成首乘 / 未领完新手礼包新手任务线逐日引导；首乘奖励翻倍；前 3 天登录奖励 ×2
活跃7 天内登录每日任务完成率 ≥ 50%日常任务 + 周目标 + 限时活动；维持即可
核心等级 ≥ 10 或周里程 ≥ 500高里程 / 高消费专属徽章、新玩法内测资格、等级折扣
沉睡7~30 天未登录最后一次登录距今 > 7 天回归礼包 + 推送"你的列车已到站待发车"
流失> 30 天未登录—大额回归礼包（¥800+）；只做短信/邮件，不骚扰

分层是运营后台的核心功能：每层人数、转化漏斗、策略触达效果都要可视化（见 §10）。

9 · 数值平衡模型（数学验证，不是拍脑袋）

9.1 产出 / 消耗平衡

项目数值说明
常规日产出≈ ¥560任务 460 + 分享 90（3 次）+ 升级均摊 ~10
登录奖励均摊≈ ¥174/天7 日循环总计 1220 ÷ 7
总日产出≈ ¥730（上限 800）打卡/邀请为额外脉冲
日均消耗≈ ¥600~900每天 1-2 次中短途（平均 ~¥450/次）
周净结余≈ +¥2000用于涂装/徽章等大额消费

结论：日常轻微赤字 + 周结余可观——用户"不签到就缺钱"（天天来），但"签到一周能买大件"（有盼头）。这是游戏经济最经典的平衡点。

9.2 成长曲线（指数，防速通）

升级所需里程 = 500 × 1.4(等级-1)　Lv2=500 · Lv5=1,921 · Lv10=10,336 · Lv15=55,617 · Lv20=299,045

京沪全程 1221km ≈ Lv2 的一半。坐完全国 7 条线约 1 万 km = Lv10。指数曲线让前期升级快（正反馈）、后期慢（长期目标）。

9.3 等级折扣（老用户特权）

票价折扣 = min(20, ⌊等级/5⌋ × 2)%　Lv5 -2% · Lv10 -4% · Lv20 -8% · Lv25 -20%（封顶）

折扣让"老玩家买车票更便宜"→ 等级不只是数字，是真金白银的省钱，强化"老用户优越感"。折扣同时轻微降低消费 → 给高等级用户留出皮肤消费空间。

9.4 通胀控制三闸门

  • 产出上限：日金币获取硬上限 ¥800（超出的打卡/分享不计入，防止刷子）
  • 大额回收：涂装 ¥3000 / 徽章框 ¥1500 —— 每 2 周上架 1 款，持续抽干沉淀
  • 定期清积分：积分每季度活动兑换，过期 50% 失效

模块功能谁用

打卡点管理录入/编辑打卡点（名称、坐标、二维码、奖励额度）——商家入驻入口商家运营

关键认知： 没有后台的数值系统 = 写死的代码，改一次发一次版。运营的价值在于随时可调——所以数值全部配置化，是这套体系能"活"的前提。

11 · 商业化预留（卖家 / 商家怎么参与）

模式机制商家收益用户收益
商家打卡点（P3 核心）商家入驻后台录入打卡点 → 用户到店打卡得积分 → 积分兑换商家券/优惠线下到店客流（真金白银的导流）积分 → 真实优惠，游戏外收获
广告位行程页/结算页 banner，可关广告收入看广告得金币（可选）
会员月费制：每日任务双倍、专属车次、无广告订阅收入省时间 + 特权感
皮肤商城涂装/徽章框内购直购直接收入个性化

顺序原则：先有用户量（P0-P1），再有商业化（P2-P3）。商家打卡放在最后——因为它依赖"用户规模 + 运营后台 + 合规审核"三件事同时就绪。

13 · 风险与对策

⚠️ 金币通胀：产出持续 > 消耗 → 金币贬值、失去激励。
对策：日产出上限 ¥800 + 每 2 周 1 款涂装回收 + 每周看板监控"人均金币存量"，存量连续 2 周上升 10% 即上调消耗或下调产出。
⚠️ 打卡作弊：虚拟定位刷打卡。
对策：GPS 围栏 + 扫码双通道；同点 24h 限 1 次；异常频率（1 小时 >3 点）自动标记人工审核。
⚠️ 刷邀请：小号互刷。
对策：设备指纹 + 注册到首乘间隔 <5 分钟不结算；首乘才发大奖。
⚠️ 平衡失灵：任务太简单/太难。
对策：任务完成率看板（目标 60-85%），低于 50% 降难度，高于 90% 提要求——数值是运营出来的，不是设计出来就不动的。
