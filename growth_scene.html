🚄 铁旅 · 用户场景与产品路径规划

用户大部分时间不在车上。产品要覆盖的，不只是"坐车的 2-8 小时"，还有"不坐车的 300 天里他们在想什么"——把用户自发的行为流程化成产品功能，但不做社区。

0 · 怎么反复思考这个产品：三问框架

每次产品决策前，反复问三个问题，直到答案具体到"某个人在某天的某个时刻"：

① 谁哪类人群？（商务/旅行/探亲/铁道迷）
→
② 何时在哪个时段？（行前/行中/到站/不坐车）
→
③ 为何他此刻想干什么？（查票价/回忆/期待/分享）
→
功能这一步产品帮他完成什么？

产品思考的完整链条：用户生命周期五段——种草 → 规划 → 乘车 → 回忆 → 惦记下次。每一段都要回答"用户此刻在想什么、我帮他做什么"。

最容易犯的错（我犯过）：只盯着"乘车"这一段做功能（因为坐车时产品最"像游戏"）。但乘车只占用户生命的 1%，另外 99% 的时间用户在想"下次去哪"——那才是留存的战场。

1 · 人群细分（不同的人，不同的"不坐车时"）

人群出行频率坐车时的需求不坐车时关注什么
商务出差党高（每周/月）效率、准点、中转衔接下次出差安排、高铁常客权益、出差城市吃喝/酒店、报销票据
周末/假期旅行者中（每 1-3 月）风景、拍照、旅途趣味目的地种草 → 攻略收藏 → 比价 → 倒计时（完整"期待链"）
学生/探亲族低（寒暑假/节假日）票价、时间、行李放假倒计时、票价变动、给家人的礼物
铁道迷/运转党特殊高线路、车型、站序、时刻新开线路、新车型、运转记录整理、线路图收藏
结论： "不坐车时"不是空窗，而是四种人群各有各的惦记。产品不必一次满足全部，但至少要知道——最大的群体（旅行者）的不坐车时段，全在"期待链"上：种草→收藏→比价→倒计时。这就是产品该接住的需求。

3 · 怎么一步步观察用户：研究方法阶梯

1
自我模拟（今天就能做）
把自己当目标用户，走一遍"想出去玩→找攻略→查票价→订票→坐车→发朋友圈"的完整流程。每步记录：我在哪搜的、搜什么词、为什么停在这。目标：还原用户的"手动工作流"——这个工作流就是产品要流程化的对象。
2
二手数据观察（本周能做）
看小红书/抖音/微博上高铁旅行相关内容的点赞收藏——什么内容火，就是什么需求强。看 12306/智行热搜、节假日出行报告。免费、快、量大。列一张"用户自发行为清单"。
3
真实访谈（1-2 周）
问 5-10 个身边常坐高铁的人 4 个问题：① 坐车前你会做什么准备？② 坐车时你会干什么？③ 下车后你会做什么？④ 不坐车的时候，什么会让你想到旅行？答案直接给功能清单。
4
埋点验证（产品上线后持续）
每个页面记录：点击率、停留、流失。用数据回答"我猜的用户行为对不对"。研究是循环不是一次性的——上线才是研究的开始。
核心方法： 研究的目的是找出用户在别的平台/现实世界里"手动做的事"——这些行为就是产品功能的候选清单。用户已经用脚投票了：他愿意做，只是没有趁手的工具。

4 · 核心命题：自发行为 → 流程化产品功能（不做社区）

用户自发行为（真实世界）现在怎么做（麻烦）流程化成产品功能对应时段
收藏想去的地方小红书收藏夹 + 备忘录，散落各处愿望清单：收藏目的地城市/景点，标注"想去"，将来购票时自动关联种草
查什么时候票价便宜反复刷 12306/智行对比票价日历：某区间未来 30 天票价视图 + 降价提醒规划
做行程计划Excel / 备忘录手写连续行程规划：A→B→C 多段中转，一次建好，自动衔接规划
记录旅程相机 + 朋友圈九宫格旅程卡自动生成（车次+线路+风景+里程，已规划 P0）到站
翻看回忆翻相册、翻车票旅程档案：足迹地图（去过的城市点亮）+ 年度旅行报告（像支付宝年度账单）+ 时间线回忆
惦记下次出发记在日历/心里出行倒计时：购票自动记录，"距出发还有 X 天"，每天打开的第一眼惦记
铁道迷整理运转记录Excel/论坛手动记录线路收藏 + 打卡成就（"已集齐 X 条线"，成就系统已有）回忆
分享旅途发朋友圈旅程卡分享：一键生成图片转发（出口，不做社区）到站后

5 · 不做社区，做什么？——边界明确

不做（社区）做（个人工作流 + 出口）
内容用户发帖、评论、点赞、关注官方编辑的攻略/目的地推荐（如"本周热门目的地"）
互动陌生人社交、私信分享出口：旅程卡生成图片 → 用户发到微信/朋友圈（我们只做"导出"，不做"圈内"）
数据公开排行榜单（刷子重灾区）个人资产：我的旅程档案、我的足迹、我的愿望清单（私有，用户自赏）
运营UGC 审核、社区治理官方内容 + 节日活动（中秋赏月专列等）
为什么不做社区是聪明决定： 社区 = 内容供给 + 审核 + 治理 + 反垃圾，运营成本极高，且会稀释"旅途伴侣"的定位。我们要的是把用户单人的"流程"做顺（种草→比价→买票→记录→回忆→惦记），这一个人闭环做好，分享行为自然会带来传播（旅程卡带邀请码），传播靠产品机制，不靠社区运营。

6 · 杀手级功能：出行倒计时（衔接 v0.1 数值体系）

为什么它是杀手锏——它把"不坐车的 300 天"和"每天打开产品"完美焊在一起：

购票自动记录出发日期
→
首页倒计时"距 G1 出发还有 12 天 6 小时"
→
每天打开的理由倒计时 + 签到 + 期待感
→
出发日旅程卡自动生成
→
下次购票…循环
  • 对用户：倒计时是"期待"，不是"任务"——用户来产品是"看我的行程"，顺便签到（名正言顺）
  • 对数值体系（v0.1）：签到奖励从"为签到而签到"变成"为我的旅行做准备"——动机升华
  • 可加升级玩法：出发前连续签到 7 天 → 本次旅程卡升级"金色纪念版"（v0.1 的 7 日循环奖励顺势而为）
  • 技术成本极低：只需在购票时多存一个日期字段，首页多一行文字——性价比全场最高

7 · 优先级与节奏（结合 v0.1/v0.2 已定计划）

阶段内容覆盖时段理由
P0（进行中）旅程卡 + 专注模式 + 个人中心 + 隐藏式签到任务到站 / 日常v0.2 已定，先把"不打扰+记忆"立住
P0.5（强烈建议插队）出行倒计时（购票自动记录）+ 旅程档案基础版（足迹城市点亮）惦记 / 回忆成本极低、覆盖"不坐车时段"、给签到一个正当理由
P1愿望清单 + 票价日历/降价提醒 + 邀请 + 排行种草 / 规划 / 传播把"期待链"的前端接住
P2运营后台 + 连续行程规划 + 年度旅行报告全时段后台是运营前提；连续行程是深度功能
P3LBS 打卡 + 商家入驻 + 会员线下商业化，依赖用户规模
节奏原则： 先接住"用户已经在做的事"（记录/回忆/惦记——成本低需求真），再引导"我们希望用户做的事"（种草/比价——需要运营内容支撑）。不要创造需求，要流程化已有需求。

8 · 三版规划的关系（完整产品设计）

版本回答的问题一句话
v0.1 数值体系有什么资源、怎么给、怎么回收骨架：经济的规矩
v0.2 体验分层放在哪、藏起来还是露出来皮肤：不打扰的规矩
v0.3 场景路径用户什么时候来、来干什么心脏：产品存在的理由（覆盖用户全部时段，不只是坐车）

三版合起来：v0.3 决定"为什么来"，v0.1 决定"来了给什么"，v0.2 决定"给的姿势不烦人"。缺任何一个，产品都不完整。
