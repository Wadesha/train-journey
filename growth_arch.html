🚄 铁旅 · 产品架构与体验分层设计

v0.1 解决了「有什么」（数值体系）——本版 v0.2 解决「怎么摆、怎么藏、给谁用」：不打扰用户 + 结合真实出行场景 + 面向真实旅客人群。
版本 v0.2 · 2026-08-19 · 前置依赖：v0.1 数值运营体系规划（全部保留）· 状态：规划稿

0 · 这一版回答的三个问题

问题答案（一句话）
① 运营会不会打扰用户？会，除非做体验分层——核心功能常驻，运营功能藏起来、只在用户完成动作后"顺带"出现。
② 这不是纯游戏，是什么？是陪伴真实高铁旅程的轻游戏化出行工具——核心价值是"记录旅程、让坐车不无聊"，数值只是调味。
③ 人群有什么特点？真实旅客：碎片时间、单手竖屏、网络不稳、电量焦虑、不想被游戏绑架但愿意被旅途打动。
总原则： 用户打开产品的目的是"坐车"，不是"做任务"。所有运营元素要么藏起来，要么顺水推舟——绝不允许挡住"坐车"这件事本身。

2 · 「不打扰」铁律：三层功能分级

2.1 三层功能分级模型（所有功能先分级，再决定怎么摆）

层级定位呈现方式典型功能
L1 核心用户来的目的永远常驻、最醒目选站 / 车次 / 行程模拟 / 报站 / 窗外风景
L2 陪伴锦上添花在用户完成自然动作后出现（顺水推舟）旅程手账 / 成就 / 旅程卡 / 拍照
L3 运营增长工具藏于入口，用户主动进入才显示签到 / 每日任务 / 邀请 / 打卡 / 排行榜 / 回归礼包
核心判断： 签到、任务、邀请、打卡、排行——全部都是 L3。它们只存在于"个人中心"一个入口里，用户不点开 = 完全不存在。这绝不降低它们的价值（该给的奖励照给），只是不占据用户的注意力。

2.2 五级打扰阶梯（渐进披露，绝不越级）

① 无提醒完全静默（默认态）
② 小红点入口上一个小点，可忽略
③ 数字角标如"可签到"，点开才知道
④ 轻提示条底部非阻断横幅，5 秒消失，可关
⑤ 弹窗仅限关键动作后（到站结算），其余禁用

规则：运营内容默认停在 ①②，最多到 ③；④ 只允许"回归礼包"这类召回场景；⑤ 只允许绑定在"到站结算"这种用户主动完成动作的瞬间。

2.3 三条铁律

  • ① 永不打断核心操作：购票流程、行程模拟中禁止任何弹窗/横幅（奖励静默入账，稍后结算页才提示）。
  • ② 奖励跟着动作走：所有运营奖励都挂在"用户已完成的行为"之后发放——坐完车才显示"今日任务 +1 完成"，绝不提前诱惑、绝不中途打断。
  • ③ 专注模式：设置里一键关闭全部运营通知（红点/角标/横幅），用户可 100% 只使用核心功能——运营功能全部可插拔，拔掉后产品依然是完整可用的出行工具。

3 · 功能 × 场景 时间轴（用户真实的一天）

阶段场景核心功能（L1）运营出现方式（L3）
行前查车次 / 候车车次查询、线路浏览、票价仅个人中心入口一个小红点（可签到），其余全隐藏
行中乘车 1-8h行程模拟、报站、窗外风景、拍照零打扰：全程无任何运营元素；到站瞬间才"顺带"显示成就/任务进度
到站下车瞬间行程结算唯一允许"弹窗"的时机：结算页自然展示「本次旅程里程碑 + 今日任务进度」（用户主动完成动作后的奖励时刻）
日常不坐车时手账回顾、收藏个人中心里：签到 / 任务 / 邀请 / 打卡 / 排行
关键洞察： 用户在"行中"是被动的（坐车没事干），注意力天然在场——这是陪伴层发挥的时间；用户在"行前/日常"是主动的（要查信息），注意力稀缺——这是运营层必须藏起来的原因。打扰阈值随时段变化，运营强度也随时段变化。

4 · 架构重构：Core / Companion / Growth 三层

L3 · Growth 运营层（可插拔，默认隐藏）
签到 · 每日任务 · 邀请 · 打卡 · 排行榜 · 回归礼包 · 积分商店 —— 全部收在「个人中心」入口；拔掉这一层，产品依然完整可用（单机回退）
L2 · Companion 陪伴层（被动记录，适时呈现）
旅程手账 · 成就 · 旅程卡（自动生成） · 风景照收藏 —— 只记录不打断，在「到站结算」「个人中心」呈现
L1 · Core 核心层（永远可用，最醒目）
真实车次查询 · 选站购票 · 行程模拟 · 报站广播 · 窗外风景 —— 用户来的目的，不依赖任何运营系统

架构三条原则

  • 单向数据流：Core 产生行为（坐车/拍照）→ Companion 记录（手账/成就）→ Growth 消费（任务计数/签到奖励）。上游永远不依赖下游。
  • 解耦回退：Growth 层任何功能下线，不影响 Core+Companion；甚至整层删除，游戏照常玩。
  • 离线优先：隧道/弱网下，Core 与 Companion 全本地可用（静态资源 + localStorage 已满足）；Growth 层需网络的玩法（排行/邀请）自动降级隐藏，不报错。

6 · 人群适配：真实出行场景的技术对策

旅客真实痛点对策
网络不稳（隧道/弱网）全部静态资源本地加载；行程模拟全程无需网络；涉及网络的玩法自动降级隐藏
电量焦虑低功耗模式（关闭高耗 rAF 动画/降低刷新率）；深色主题默认（OLED 省电）
竖屏单手操作底部操作栏 + 大按钮 + 拇指可达区域设计；选站→购票 3 步内完成
碎片时间每次核心操作 ≤10 秒；行前查车次、候车浏览、行中看风景各是独立可中断的单元
不想被"游戏"绑架专注模式：一键关闭全部运营通知；奖励照发但完全静默
旅途情感价值每段旅程自动生成「旅程卡」：车次 + 线路 + 途经城市 + 风景照 + 里程 —— 可保存、可分享，成为用户真实的旅途记忆
人群核心画像一句话： 他们不会为"游戏"停留，但会为"我的旅程"停留。产品必须让用户觉得"这是我的出行工具，顺便有点趣味"，而不是"这是个游戏，我在里面做任务"。

7 · 调整后的实施路线

P0 · 核心+陪伴（v0.2）
  • Core 不动（真实车次已就绪）
  • 旅程卡自动生成（到站结算瞬间）
  • 专注模式（一键关运营通知）
  • 个人中心入口（签到/任务藏于此）
  • 签到 + 每日任务（L3 隐藏式）
  • 存档结构扩展（兼容旧档）
纯前端，立即可测；本版即可上线
P1 · 传播（v0.3）
  • 旅程卡分享（自动带邀请码）
  • 邀请两段奖励
  • 周里程目标 / 回归礼包（轻提示条）
  • 排行榜（个人中心内）
需轻后端（邀请/排行）
P2 · 运营后台（v0.4）
  • 数据看板（DAU/留存/流水）
  • 任务/数值配置化（不改代码调参）
  • 用户管理 / 活动管理
需后端
P3 · 线下结合（v0.5）
  • LBS 打卡 + 扫码打卡
  • 商家入驻 + 打卡点管理
  • 积分商店 / 会员 / 皮肤
需合规 + 商家 BD

变化说明：与 v0.1 相比，P0 重心从"数值功能"转向"旅程卡 + 专注模式"——先把"不打扰 + 旅途记忆"这两个产品本质立住，再上增长工具；签到任务虽在 P0 但以 L3 隐藏形式存在。
